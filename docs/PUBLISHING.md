# ブラウザから記事を編集・公開する

[Pages CMS](https://app.pagescms.org/)でGitHubへログインし、`97kuek/portfolio`と`main`ブランチを選びます。左側の「記事」から、既存の記事を開くか新しい記事を作成します。設定はリポジトリ直下の`.pages.yml`です。

初回のGitHub App連携では、書き込み対象を`97kuek/portfolio`だけに限定します。GitHub Appはコード・Actions・リポジトリ作成の読み書きと、checks・status・deployments・metadata・Pagesの読み取りを要求します。利用者の認証ではメールアドレスの読み取りも要求されます。記事フォーム以外への権限もあるため、GitHubの確認画面で対象と権限を確認してください。

## 新しい記事

1. `Filename`を`new-article.md`から、`azure-search-notes.md`のような半角英数字とハイフンの名前へ変更します。
2. タイトル、公開日、URLの識別名、本文を入力します。URLの識別名は、同じ言語の記事と重複しない半角英小文字・数字・ハイフンで64文字以内にします。
3. 下書きのまま保存します。新規記事は下書きが既定で、サイトには表示されません。
4. 公開するときは「下書き」をオフにして保存します。

保存するとGitHubへコミットされ、検証とデプロイが成功してからサイトに反映されます。公開日は予約公開の設定ではありません。未来の日付でも「下書き」をオフにすると公開対象になります。

作成後のファイル名は変更できません。公開済み記事のURLの識別名を変えると、以前のURLやコメントの参照先が変わるため、通常はそのまま使います。

## 本文と画像

本文は管理画面内のMarkdown編集欄を使います。コード、表、数式、折りたたみ、callout、wikilink、脚注を既存の記事と同じ記法で保存できます。タイトル・タグ・日付・下書きなどはフォームで編集します。

カバー画像はフォームから選択できます。本文に画像を入れるときは画像管理へアップロードし、次の形で挿入します。

```markdown
![何が写っているか分かる説明](../../assets/photos/example.jpg)
```

画像の説明は公開ページのキャプションになります。画像はアップロード前に長辺2400px程度へ圧縮します。

更新日は空欄でも保存できます。指定する場合は公開日より後の日付にします。

## 英語版

英語版は別の記事として作成します。たとえば日本語版が`azure-search-notes.md`なら、英語版は`azure-search-notes-en.md`にします。

- 言語を「英語」にする。
- URLの識別名には、日本語版と同じ`azure-search-notes`を指定する。

翻訳同士は識別名を共有し、日本語は`/blog/azure-search-notes`、英語は`/en/blog/azure-search-notes`で公開されます。

## 保存後に反映されない場合

[GitHub ActionsのCI](https://github.com/97kuek/portfolio/actions/workflows/ci.yml)を確認します。記事や画像の変更は、型検査・ビルド・ブラウザ検証の対象です。エラーがある場合は、日付、概要の200文字制限、想定する読者の300文字制限、URLの識別名、画像パスを確認してください。

`README.md`など運用ドキュメントだけの変更は重い検証と配信を省きますが、`src/content/`の記事や`.pages.yml`は省略しません。
