## 概要

OpenAI Dotsによる対話・サービス連携と、Mac上でのコード実行やデータ同期を組み合わせたパーソナルアシスタントです。
研究、大学の課題、仕事、時間記録をモジュールとして扱い、必要な機能だけを有効にできます。

このページでは技術構成と実装上の判断をまとめます。日常での使いどころや導入の流れは、ブログの[「OpenAI Dotsでパーソナルアシスタントを作ってみた」](/blog/kei-agent)に分けています。

## アーキテクチャ

| 層 | 役割 | 主な技術 |
| --- | --- | --- |
| 対話・連携 | Slack・通話の依頼を受け、プラグインで情報を扱う。ローカル作業をMCPへ渡す | OpenAI Dots、プラグイン |
| 実行サービス | MCPの受付、実行状態、通知、定期処理を管理する | Python、MCP、SQLite |
| 担当プロセス | 作業場に対応するアカウントと権限で処理する | A2A、Claude Code／Codex CLI |
| 取り込み・保存 | MoodleやTogglのデータを取り込み、Notionなどへ同期する | 外部API、Notionゲートウェイ |

Mac側は`launchd`で常駐させます。プロセス間の通信はループバックに限定し、DotからはSecure MCP Tunnelを通じてMCPサーバーを呼び出す構成です。
Macの実行サービスはSlackに直接接続せず、受け答えや投稿はDotが担当します。

## MCPによる非同期実行

ローカル作業の入口は`workspaces`・`run`・`status`です。

1. `workspaces`で利用可能な作業場と実行エンジンを取得する。
2. `run`へ作業場、依頼、処理の重さなどを渡す。
3. 短時間で終われば結果を返し、長い処理は受付番号を返す。
4. `status`で待機中・実行中・完了・入力待ち・失敗の状態と結果を取得する。

作業場から担当・アカウント・権限を解決し、A2A経由で担当プロセスへ処理を渡します。
研究にはClaude CodeまたはCodexのCLI、仕事には会社のClaude Codeを使います。
実行記録には担当、用途、provider、モデル、経過時間、費用、失敗を残します。

通知はOutboxへ保存し、Dotが`notices`で取得します。投稿成功の確認応答を受けるまで通知を残すことで、取得と配信完了を区別しています。

## モジュールと外部連携

各機能の宣言は`module.toml`、有効化やアカウントの対応は`agents.csv`、定期実行は`schedules.csv`で管理します。
モジュールのAPIバージョン、設定キー、用途やポートの重複を読み込み時に検証する設計です。

- **研究・仕事**：テーマやプロジェクトごとの作業ディレクトリで、コードの変更やテストを実行する。
- **大学**：AIを介さずMoodleの締切を取り込み、API設定時には提出・受験終了の状態も同期する。
- **時間記録**：MCPのタイマーから計測し、Toggl・Notionと連携する。
- **Notion**：ローカルのゲートウェイで、利用する担当ごとにアクセスできるホームを絞る。

大学の資料への質問や新しい読みものの検索・要約は、Dot側のプラグインで扱います。
機械的な同期と、AIが判断する処理の実行場所を分けています。

## 権限と実行環境の分離

書き込み可能な範囲、読み取りを拒否する場所、外部通信、子プロセスへ渡す環境変数を、実行サービス側で制御します。
会社のデータを読む担当には外部通信を許可せず、アカウントの異なる担当の作業場や秘密情報もアクセス制限の対象とします。

Claude CodeとCodexには担当ごとの設定を渡し、利用者の通常の設定をそのまま持ち込まないようにしています。
Dot側のプラグイン認証と、Mac上で実行する担当の認証は別に管理します。

## 運用と拡張

`kei-agent setup`で設定・常駐サービスを準備し、`kei-agent doctor`で状態を点検します。
モジュールのひな形作成、テスト、有効化にもCLIを用意しています。

朝の一覧や夜の振り返りをDotへ移した場合は、対応するローカルの定期処理を停止します。
Mac側には秘密情報を使う取り込みや保守・バックアップを残し、同じ処理の二重実行を避けます。
Macがスリープ中はローカル実行と同期が止まり、同期先の情報は最後に取り込んだ状態になります。

実装と詳しい設定は[GitHubリポジトリ](https://github.com/97kuek/kei-agent)で管理しています。
